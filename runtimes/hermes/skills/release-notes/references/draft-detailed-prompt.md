# [ЧЕРНОВИК] Детальные промпты release-notes (legacy)

> Источник: удаленный микросервис `agent-release-notes` (эпоха микросервисной архитектуры).
> Статус: НЕ используется рантаймом. Сохранено для ревью и возможного обогащения `../instructions-*.md`.
> Чтобы включить: перенести нужные разделы в соответствующие `../instructions-*.md` и проверить качество на реальных кейсах.

---

## Вариант release_notes

Сгенерируй ТОЛЬКО release notes на русском языке.

Требования:
- Не добавляй changelog.
- Не добавляй разделы Added / Changed / Fixed / Removed.
- Сделай человекочитаемый список изменений для пользователей без лишних технических деталей.
- Сгруппируй изменения по типам: Новые возможности, Улучшения, Исправления.
- Убери служебные коммиты: merge, bump version, chore, dependency update и похожие.
- Если по коммитам или задачам нельзя уверенно определить пользовательскую ценность, сформулируй осторожно и без выдуманных деталей.
- Если данных мало, все равно сформируй краткие release notes по доступным названиям задач; не возвращай пустой ответ.

Общие правила:
- Пиши на русском языке нейтральным техническим стилем.
- Не добавляй вступительные и заключительные фразы.
- Не придумывай факты, которых нет в задачах, коммитах или переданном тексте.
- Сохраняй ключи Jira, имена репозиториев, версии, компоненты и технические термины без изменений.

## Вариант changelog

Сгенерируй ТОЛЬКО changelog на русском языке.

Требования:
- Не добавляй release notes для пользователей.
- Используй Markdown.
- Используй структуру: Added / Changed / Fixed / Removed, но содержимое пунктов пиши на русском языке.
- Добавь заголовок с репозиторием/источником и периодом.
- Классифицируй изменения по смыслу коммитов или задач.
- Убери служебные коммиты: merge, bump version, chore, dependency update и похожие.
- Не оставляй англоязычные описания коммитов без перевода.

Общие правила:
- Пиши на русском языке нейтральным техническим стилем.
- Не добавляй вступительные и заключительные фразы.
- Не придумывай факты, которых нет в задачах, коммитах или переданном тексте.
- Сохраняй ключи Jira, имена репозиториев, версии, компоненты и технические термины без изменений.

## Вариант сопоставления release notes ↔ Jira

Сопоставь каждый пункт Release Notes с наиболее подходящей Jira-задачей.
Ответь только итоговым сопоставлением на русском языке простым Markdown-списком.
Не используй жирный шрифт, таблицы, HTML или декоративное форматирование.
Для каждого пункта укажи ключ Jira и короткое объяснение совпадения.
Если для пункта нет уверенного соответствия, укажи: Jira не определена.
Не придумывай факты, которых нет в Jira-задачах или Release Notes.
