# doc-reviewer

## Продуктовый контракт

- Вход: текст документации в сообщении (route `review`), файл `.pdf` / `.doc` / `.docx` / `.md` / `.markdown` / `.txt` до 50 МБ (route `review_file`) или ссылка на страницу документации (route `review_url`).
- Выход: замечания по разделам в формате «+ что хорошо / - что исправить / Рекомендация» и итоговая строка `Итог: X критичных / Y важных / Z рекомендаций`.
- Стайлгайд опционален: если пользователь сохранил его командой «это стайлгайд», он применяется к каждому ревью.

## Правила

1. Документ не переписывается целиком; факты, отсутствующие во входных данных, не добавляются.
2. Системный промпт загружается из `instructions.md`; ответ очищается от Markdown-разметки (`hermes/app/skills/reviewer.py::_clean_markdown`).
3. Стайлгайд — локальное состояние рантайма (`hermes/state/styleguide.md`, вне пакета и вне git).
4. Текст файлов извлекается детерминированно (`hermes/app/skills/documents.py`), текст страницы — детерминированным HTML-парсером (`hermes/app/skills/webdocs.py`): скрипты, стили, меню, шапка, подвал и скрытые блоки отбрасываются, приоритет у `<main>` / `<article>`. LLM получает только готовый текст.
5. Страница читается только по HTTP(S) методом GET (5 МБ, 40000 символов максимум); при 401/403/404, пустой странице или SPA-рендеринге возвращается явная ошибка без вызова LLM.
6. Источник текста (имя файла или URL) передается в промпт отдельной строкой, чтобы замечания ссылались на него.

## Файлы

- `instructions.md` — живой системный промпт, используется рантаймом.
- `references/draft-detailed-prompt.md` — детальный legacy-промпт (черновик, не используется рантаймом).
